# Реестр рисков зависимостей

Документ отслеживает внешние зависимости с нетривиальным риском из-за статуса сопровождения, проектов с единственным мейнтейнером или изменений в upstream. Каждая запись включает оценку риска и стратегию митигации.

Закреплённые версии берутся из [`go.mod`](../../../go.mod), принятие риска —
из [`scripts/vuln-audit.go`](../../../scripts/vuln-audit.go) и задачи владельца
в Beads. Реестр не заменяет свежие проверки финальных графов рабочего модуля
и инструментов и не устанавливает текущее число сопровождающих upstream.

## x/net/html — Исправленные уведомления

Графы рабочего модуля и инструментов выбирают `golang.org/x/net v0.62.0` —
исправленную версию для [GO-2026-6860](https://vuln.go.dev/ID/GO-2026-6860)
и [GO-2026-6866](https://vuln.go.dev/ID/GO-2026-6866).
Оба уведомления опубликованы 2026-10-27. Исключения allowlist для них отсутствуют.
Обновление также меняет код транспорта IPv4, используемый interop peer;
его транспортные тесты сохраняются вместе со свежим security scan финального кандидата.
Приёмка релиза отслеживается в Beads `gobfd-qj0.8.4.1`.

## reeflective/console — Средний риск

| Поле | Значение |
|------|----------|
| **Модуль** | `github.com/reeflective/console v0.5.0` |
| **Используется в** | `cmd/gobfdctl/commands/shell.go` — интерактивная REPL-оболочка |
| **Уровень риска** | Средний |
| **Причина** | API до v1.0 и зависимость от внешнего сопровождения |

### Описание

Библиотека `reeflective/console` обеспечивает интерактивную оболочку для `gobfdctl`. Она оборачивает команды Cobra в REPL на основе readline с дополнением по Tab, историей и настройкой приглашения.

### Факторы риска

- **API до v1.0**: Библиотека не достигла v1.0; между минорными версиями возможны несовместимые изменения API.
- **Внешнее сопровождение**: Перед обновлением заново проверьте состав сопровождающих и активность выпуска версий upstream.
- **Транзитивные зависимости**: Подключает модули readline, дополнения команд и терминального интерфейса.
- **Нет альтернативы в stdlib**: Стандартная библиотека Go не включает Cobra-совместимый REPL-фреймворк.

### Митигация

1. **Фиксация версии**: Зависимость закреплена на `v0.5.0` в `go.mod`.
   [Проект обновления зависимостей](../../superpowers/specs/2026-08-18-v0.6.2-dependency-refresh-design.md#go-module-closure)
   фиксирует переход с `v0.1.25` на `v0.5.0`; историческая запись не заменяет
   квалификацию CLI и race-тесты финального кандидата.
2. **Вендоринг**: Если проект станет заброшенным, вендорить исходный код в `internal/console/`.
3. **Область выполнения**: Неинтерактивные команды не запускают REPL. Бинарник CLI
   по-прежнему зависит от модуля при сборке; эта зависимость не является необязательной.
4. **Ограниченная область**: Интеграция находится в `shell.go`;
   демон и реализация протокола не импортируют пакет console.

## osrg/gobgp — Высокий риск

| Поле | Значение |
|------|----------|
| **Модуль в `dev`** | `github.com/osrg/gobgp/v4 v4.10.0`; импортируется только `github.com/osrg/gobgp/v4/api` |
| **Модуль в `release/v0.6`** | `github.com/osrg/gobgp/v3 v3.37.0` |
| **Используется в** | `internal/gobgp/` — опциональная интеграция GoBGP |
| **Известное уведомление об уязвимости** | `GO-2026-4736` / `CVE-2026-30405` / `GHSA-4p9m-8gc4-rw2h` |
| **Уровень риска** | Высокий |
| **Владелец allowlist** | `@dantte-lp` |
| **Дата окончания действия (пересмотра)** | `2026-12-31` |

### Описание

Основание принятия риска в [`scripts/vuln-audit.go`](../../../scripts/vuln-audit.go)
и [SECURITY.md](../../../SECURITY.md) относится к уведомлению об отказе в обслуживании
при обработке BGP NEXT_HOP. Оно фиксирует исправленную v4.4.0 в GHSA-4p9m-8gc4-rw2h
(upstream commit `583080a`) и отсутствие исправленной версии v4 в базе уязвимостей Go
для `fsmHandler.recvMessageloop` в `github.com/osrg/gobgp/v4/pkg/server`.
GoBFD импортирует пакет API. Записанное принятие риска в `dev` охватывает только
находки govulncheck и OSV на уровне модуля; свежее сканирование финального кандидата
должно подтвердить эту границу. Реестр не устанавливает текущее содержимое баз уязвимостей.

GoBGP v3 обслуживает `/apipb.GobgpApi`, v4 — `/api.GoBgpService`; они
несовместимы на уровне протокола. GoBFD в `dev` требует демон GoBGP v4. Принятие риска для
v0.6 ниже фиксирует воздействие на v3.37.0; запись не устанавливает, выпустил
ли upstream исправление позднее.

### Митигация

1. **Ограничение доступности**: путь GoBGP является опциональным и должен
   подключаться только к конечной точке gRPC GoBGP на localhost или в доверенной
   сети управления.
2. **Контролируемый CI allowlist в `dev` и stable v1**: по решениям
   сопровождающего от 2026-10-13 и 2026-10-21 (stable v1, `gobfd-qj0.8.4.1`) запись
   `GO-2026-4736` имеет режим `ModuleOnly` для точного модуля
   `github.com/osrg/gobgp/v4` и содержит владельца `@dantte-lp`, дату окончания действия
   (пересмотра) 2026-12-31, основание и меры снижения риска. Stable v1 дополнительно
   требует, чтобы GHSA/OSV указывали исправленную версию не выше закреплённой,
   а govulncheck финального кандидата сообщал об уязвимости только на уровне модуля.
   Достижимый символ, импортированный затронутый пакет, несовпадение пакета,
   неизвестный сканер, дополнительная уязвимость, просроченная или устаревшая запись
   без соответствующей находки завершают CI ошибкой.
3. **Принятие риска в `release/v0.6`**: по решению сопровождающего от 2026-10-13
   линия v0.6 принимает риск GoBGP v3.37.0 до 2026-12-31 как границу
   поддержки при условии, что GoBGP API доступен только на localhost или в
   доверенной сети управления. Поставка в стабильную ветку отслеживается в Beads
   `gobfd-qj0.8.1.16.4`.
4. **Условие удаления**: удалить запись allowlist, когда база уязвимостей Go
   укажет исправленную версию GoBGP v4 (golang/vulndb#5035, #6562).
   После этого аудит завершается ошибкой на записи, так как она не соответствует
   ни одной находке сканеров.

## x/crypto/openpgp — Уведомление об уязвимости только на уровне модуля

| Поле | Значение |
|------|----------|
| **Модуль** | `golang.org/x/crypto v0.58.0` (непрямая зависимость) |
| **Затронутый пакет** | `golang.org/x/crypto/openpgp` (отсутствует в графе сборки) |
| **Известное уведомление об уязвимости** | `GO-2026-5932` |
| **Режим allowlist** | Только находки точного модуля при инвентаризации |
| **Дата окончания действия (пересмотра)** | `2026-12-31` |

### Митигация

1. **Затронутый пакет не импортируется**: вывод `go list -deps ./...` не должен содержать
   `golang.org/x/crypto/openpgp`.
2. **Отклонение при нарушении границы достижимости**: аудит принимает только недостижимые находки
   точного модуля `golang.org/x/crypto` от `govulncheck` или `osv-scanner`.
   Достижимый символ, затронутый подпакет, несовпадение пакета или неизвестный
   сканер завершают CI ошибкой даже при совпадении ID уязвимости.
3. **Условие удаления**: удалить исключение, когда находка при инвентаризации модуля
   исчезнет; никогда не добавлять импорт `openpgp`.

## Переход пути модуля YAML v3 — Низкий риск

| Поле | Значение |
|------|----------|
| **Модуль собственных импортов** | `go.yaml.in/yaml/v3 v3.0.5` (прямая зависимость) |
| **Устаревший модуль** | `gopkg.in/yaml.v3 v3.0.1` (только транзитивно) |
| **Используется** | Вывод CLI, конфигурация HAProxy, интеграционные тесты и транзитивный код console |
| **Уровень риска** | Низкий |

### Описание

[Проект обновления зависимостей](../../superpowers/specs/2026-08-18-v0.6.2-dependency-refresh-design.md#go-module-closure)
фиксирует архивацию `gopkg.in/yaml.v3` как причину миграции. Собственные импорты
GoBFD используют `go.yaml.in/yaml/v3`; старый путь остаётся в транзитивном
графе. До обновления заново проверьте сопровождение upstream и совместимость
API: запись о миграции не устанавливает текущее состояние upstream.

### Факторы риска

- **Записанная архивация**: Старый путь несёт риск внешнего сопровождения;
  запись о миграции не гарантирует поведение будущих релизов upstream.
- **Транзитивная миграция в ожидании**: устаревший модуль нельзя убрать из полного
  MVS-графа, пока console/Carapace не переведут свои внутренние импорты.

### Митигация

1. **Собственные импорты переведены**: код GoBFD импортирует только
   `go.yaml.in/yaml/v3`. Перед отнесением транзитивного пути к конкретному
   upstream повторите `go mod why gopkg.in/yaml.v3` на финальном графе модулей.
2. **Мониторинг upstream**: удалить транзитивный устаревший модуль после миграции
   console/Carapace, когда это разрешит `go mod tidy`.
3. **Проверка регрессий**: новые собственные импорты `gopkg.in/yaml.v3`
   запрещены.
4. **Проверка безопасности**: сканировать оба точных графа модулей до квалификации;
   архивация и закреплённая версия преемника не подтверждают отсутствие уязвимостей.

*Сверено с исходниками `dev`: 2026-10-25 (`706991db9433b13cec47e0bb8ea2549b01e948d9`); состояние upstream и результаты сканирования финального кандидата требуют отдельных доказательств.*
