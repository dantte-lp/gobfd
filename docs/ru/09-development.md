# Разработка

Разработка использует ветку следующей линии `dev` и закреплённый в репозитории инструментарий Podman. Исполняемый контракт — [AGENTS.md](../../AGENTS.md); команды определены в [Makefile](../../Makefile). Успешная проверка исходников не квалифицирует демон, сеть или выпуск.

## Подготовка рабочей копии

1. Выбрать ветку изменения. Использовать `dev` для функций и `release/vMAJOR.MINOR` для исправления поддерживаемой линии; направить pull request в ту же линию. Сохранить контракт GoBGP v3 для v0.6.
2. Установить Podman, Git, GNU Make и util-linux `flock`. Настроить закреплённый Go-провайдер Compose по [процедуре развёртывания](06-deployment.md#podman-compose).
3. Задать параллельным рабочим копиям разные `COMPOSE_PROJECT_NAME`. По умолчанию используется нормализованное базовое имя каталога; одинаковые имена конфликтуют.
4. Запустить среду разработки и проверить её проект:

```bash title="Development environment"
make up
make dev-project
make dev-ps
```

`go.mod`, `tools/go.mod` и `deployments/docker/Containerfile.dev` закрепляют Go 1.27.3. Команды сборки, тестирования и lint выполняются в dev-контейнере. `dev-ensure` проверяет bind-монтирование `/app` и может пересоздать контейнер при смене рабочей копии. `make up` может собирать образы; это не предварительная проверка только для чтения.

## Процедура изменения

1. Записать область изменения, критерии приёмки, зависимости и ответственных за проверку.
2. Прочитать затронутые вызовы, тесты, конфигурацию и публичные контракты.
3. Изменить написанные вручную исходники; перегенерировать публичный protobuf вместо редактирования `pkg/bfdpb/`.
4. Выполнить целевой race-тест, затем обычную проверку:

```bash title="Focused and routine checks"
make test-run RUN=TestFSMTransition PKG=./internal/bfd
make lint-docs
make verify
```

5. Выполнить соответствующую [проверку совместимости](05-interop.md) для изменений протокола, транспорта, аутентификации или формата на линии. Выполнить бенчмарки для изменений горячего пути или инструментария.
6. Обновить руководства на обоих языках и оба журнала изменений при смене видимого пользователю поведения. Указать в pull request точные идентификаторы исходников и бинарников, выполненные проверки, пропуски и незавершённую приёмку.
7. Запросить проверку соответствующих владельцев из [.github/CODEOWNERS](../../.github/CODEOWNERS). Следовать [CONTRIBUTING.md](../../CONTRIBUTING.md) и [руководству выпуска](10-changelog.md).

`make all` выполняет сборку, race-тесты, gopls, lint и проверки документации. `make verify` добавляет lint protobuf и контролируемый аудит уязвимостей. Он не включает совместимость с работающими соседями, жизненный цикл пакетов, эталонную нагрузку или приёмку публикации.

## Среда и сборка

| Цель | Поведение |
|:---|:---|
| `up`, `dev-ensure` | Создать или запустить выбранный dev-стек; проверить монтирование исходников |
| `dev-project`, `dev-ps` | Вывести идентификатор проекта или состояние стека |
| `logs` | Следить за журналами dev |
| `down`, `restart` | Остановить dev-стек или остановить и запустить |
| `build` | Собрать четыре бинарника с ldflags версии, commit и времени сборки UTC |
| `all`, `verify` | Выполнить описанные выше совокупные проверки |
| `versions` | Вывести идентификаторы установленных инструментов |

## Тестовые цели

| Цель | Область |
|:---|:---|
| `test`, `test-v` | Все пакеты по умолчанию, race detector, один запуск без кеша; необязательный подробный вывод |
| `test-run RUN=NAME PKG=PATH` | Целевой race-тест |
| `fuzz FUNC=NAME PKG=PATH` | Одна цель fuzz, бюджет 60 секунд |
| `test-integration` | Тесты Manager/API/моста пакетов внутри процесса с тегом `integration` |
| `testcontainers-smoke` | Обязательная smoke-проверка провайдера Podman с тегом `testcontainers` |
| `coverage`, `coverage-func` | Покрытие race-тестов; HTML или сводка функций |
| `test-report` | Race-тесты и JUnit/JSON/HTML под `reports/tests/` |
| `report-all` | Отчёт тестов, снимок бенчмарков и сравнение |
| `benchmark*`, `profile` | [Сбор бенчмарков и профили](12-benchmarks.md) |

Обычный `go test` не выполняет все наборы с тегами сборки. Мост внутри процесса не является тестом UDP или жизненного цикла процессов. Сохранить тесты виртуального времени `testing/synctest` для детерминированной логики таймеров и ограниченные реальным временем ожидания внешних соседей.

Цели fuzz охватывают кодеки Control, VXLAN, Geneve и внутреннего пакета. До запуска выбрать точную функцию пакета. Сохранить сбойные элементы корпуса и соответствующий регрессионный тест; ограниченный запуск fuzz не является исчерпывающей проверкой.

[Перечень целей E2E](../../test/e2e/targets.md) различает проверки с утверждениями, сохранённые демонстрации и проверки только манифестов. `e2e-vendor` не доказывает выполнение на платформе производителя, а именованная проверка пути действия RFC — полного покрытия RFC. Цели очистки могут удалять принадлежащие им ресурсы и требуют соответствующего разрешения.

### Проверка overlay на линии

Выполнить `make e2e-overlay` для тестов userspace UDP с утверждениями. [Запускающий компонент](../../test/internal/e2erunner/runner.go) создаёт отдельную среду `--network none`, немедленно запускает ограниченный тест и выполняет попытку удаления среды до возврата без гарантии успеха. Точек подключения для запуска, готовности или присоединения захвата нет. Захват после возврата цели не может наблюдать уже завершённый тест в этой среде.

Сохранить JSON тестов Go для обоих внутренних кортежей на общих внешних адресах и VNI. [Утверждения](../../test/e2e/overlay/wire_test.go) охватывают двунаправленный userspace UDP, TTL 255, отклонение неверной идентичности и некорректных пакетов, отмену, повторное использование и Close. Созданный `packets.csv` — сводка стенда кодека, а не PCAP.

Квалификация линии требует отдельно реализованного и проверенного жизненного цикла захвата: вход в точное пространство имён среды до трафика, подтверждённая готовность захвата, ограниченные длительность и размер файла, остановка и присоединение захвата, проверки непустых артефактов до удаления среды. Сопоставлять декодированные кадры и discriminator с принятыми и отклонёнными исходами только после появления такого жизненного цикла; сохранить команду, ID образов, ограничения и хеши. Текущая цель сама по себе не предоставляет эту квалификацию.

Повторить шесть целей fuzz overlay с race detection, двумя рабочими, бюджетом 20 секунд и внешним тайм-аутом как отдельную проверку. Эти проверки не квалифицируют backend overlay производителей или конкретных владельцев.

### Жизненный цикл пакетов

Выполнить в закреплённом SDK с проверенным UPX в PATH:

```bash
go run ./test/cmd/cictl package-build
go run ./test/cmd/cictl package-lifecycle
```

`package-build` использует закреплённый GoReleaser выпуска, тестовую версию `v0.0.0` и нативную финализацию жизненного цикла RPM. Он отключает стадии публикации и требует Git checkout. `package-lifecycle` требует API Podman и проверяет DEB в Debian с systemd: запуск, изоляцию, удержание watchdog, перечитывание с тем же PID, перезапуск после SIGKILL, остановку с мёртвым соседом, проверку unit, идемпотентность обновления при включённом и отключённом сервисе и удаление активного пакета. Стенды обновления меняют только управляющую версию пакета; они не квалифицируют обновления между реализациями демона.

Пределы сборки — 2 CPU/2 GiB. Пределы выполнения — 1 CPU/1 GiB, без swap, 1024 PID и закрытое пространство имён cgroup; тест проверяет эффективные пределы. SYS_ADMIN, SYS_PTRACE и исключения пространств имён и безопасности относятся только к этому одноразовому стенду systemd. Тестовые пакеты Debian по-прежнему разрешаются зеркалом. Доказательства находятся в `reports/e2e/package-lifecycle/`; генерация RPM отделена от приёмки DEB во время выполнения.

## Качество, protobuf и зависимости

| Цель | Контракт |
|:---|:---|
| `lint`, `lint-ci` | Канонический линтер под управлением Go с базовыми профилями и тегами сборки |
| `lint-fix` | Применить исправления линтера; проверить итоговый diff |
| `gopls-check` | Ограниченная диагностика, включая профиль генератора зависимостей Darwin |
| `lint-md`, `lint-yaml`, `lint-spell`, `lint-docs` | Markdown, YAML, выбранная английская орфография; общая проверка документации |
| `lint-commit MSG='fix(bfd): reject invalid input'` | Проверить один заголовок Conventional Commit |
| `semgrep`, `semgrep-json`, `semgrep-pro` | Выбранный исполняемый Semgrep хоста; Pro требует своего движка и доступа |
| `vulncheck`, `osv-scan` | Контролируемый аудит govulncheck + OSV |
| `vulncheck-strict`, `osv-scan-strict` | Исходные сканирования без исключений проекта |
| `proto-gen`, `proto-lint` | Перегенерировать или проверить lint определений protobuf |
| `proto-breaking`, `proto-update` | Сравнить с локальным master или обновить зависимости Buf |
| `dependency-inventory`, `dependency-inventory-check` | Сгенерировать выбранную инвентаризацию или проверить без сети |
| `tidy`, `download` | Привести зависимости runtime в порядок или загрузить их |
| `clean` | Удалить демон, CLI и кеши Go; бинарники мостов сохраняются |

CI проверяет изменения protobuf и использует точный полученный базовый commit PR для проверки несовместимости; локальный `proto-breaking` использует `master`. `tools/go.mod` владеет инструментами разработки. Разделять графы runtime и инструментов. Генерация инвентаризации фиксирует наблюдения; проверка без сети доказывает соответствие снимку, но не актуальность upstream, безопасность или принятие выпуском. Исключения advisory имеют точные границы модуля, сканера, достижимости, владельца и срока; см. [реестр рисков](reference/dependency-risk.md).

## Границы выполнения инструментов

| Точка входа | Компилятор и runtime |
|:---|:---|
| Обычные цели Make | Go внутри выбранного dev-контейнера |
| Пять совокупных проверок E2E | Компилятор без сокета движка с закреплённым digest собирает игнорируемый `bin/e2ectl`; хост запускает этот точный бинарник |
| Пять запусков Containerlab | Новая сборка закрытого контроллера без сокета движка; отдельные компилятор race-нагрузки и Debian runtime |
| Сохранённый bootstrap `interopctl` и интеграций, `benchmark-report` | Прямой `go run`; требуется явное выполнение в закреплённом контейнере или точный закреплённый компилятор хоста |
| `lint-ci` и команды CI | Прямые точки входа Go для закреплённого контейнера CI |
| `semgrep*` | Выбранный исполняемый файл хоста |

Блокировка каталога совокупной проверки E2E охватывает пересоздание dev, сборку и выполнение; получение ожидает 120 секунд. Пределы компилятора — 2 CPU/2 GiB/512 PID, исходники только для чтения, выход бинарника для записи. Пробный запуск Make печатает делегирование без создания этого каталога. Help/dry-run/down Containerlab всё равно собирают новый контроллер; старые бинарники никогда не подставляются при отказе.

Инструменты репозитория находятся под управлением Go. Не добавлять среды Python, Bash-скрипты репозитория или shell-программы в CI. Единственное исключение runtime Python — upstream ExaBGP с закреплённой контрольной суммой внутри его Debian-образа соседа. Внутренние процедуры запуска поставщика, принадлежащие пакету, не являются запускающими программами репозитория. Контракты команд приведены в [справочнике CI и выпуска](reference/automation.md).

## Правила кода и runtime

| Область | Требование |
|:---|:---|
| Ошибки | Оборачивать с контекстом и `%w`; использовать `errors.Is`/`errors.As` |
| Конкурентность | Context первым, goroutine связаны с отменой, отправитель закрывает каналы |
| Журналирование | Структурированный `log/slog`; сохранять границы чувствительных данных |
| Структура | Малые интерфейсы владельца-потребителя; группы импортов стандартной библиотеки, внешних и внутренних пакетов |
| Протокол | [RFC 5880 §6.8.6](../../docs/rfc/rfc5880.txt), интервалы в микросекундах, явные доказательства процедуры |
| Память | Измерять именованный горячий путь; исключить общие заявления о GC или масштабе |
| Unsafe и сгенерированный код | Нет написанного вручную `unsafe`; перегенерировать protobuf |
| Контейнеры | Debian trixie с закреплённым digest; сохранять поддерживаемые исторические контракты |

Сохранить vet-проверку версии стандартной библиотеки. Использовать `synctest.Sleep` только внутри детерминированных тестовых областей. Сохранить тесты совместимости JSON, именованные пределы HTTP-заголовков и существующую изоляцию pprof. Проект не устанавливает глобальное переопределение GOMAXPROCS; квалифицировать GOMEMLIMIT и сохранить GOGC по умолчанию, если измерения не обосновывают другое значение. API выпуска Go и удалённые настройки совместимости определяются [контрактом закреплённой основы](../../AGENTS.md), а не иллюстративными фрагментами.

## Диагностика

| Симптом | Проверка | Действие |
|:---|:---|:---|
| Тесты используют другую рабочую копию | `make dev-project`, `make dev-ps`, выбранное монтирование | Назначить отдельный проект и выполнить `dev-ensure` |
| Compose отказывает или сборки используют Buildx | Выбор провайдера и DOCKER_BUILDKIT | Повторить [подготовку провайдера](06-deployment.md#podman-compose) |
| Обычные тесты успешны, код с тегами отказывает | Точный профиль тегов сборки | Выполнить каноническую обёртку lint и выбранную проверку E2E |
| Отчёты расходятся с журналами | ID запуска, ревизия, отметки времени, ожидаемые файлы | Сохранить исходный вывод отказа; использовать новый каталог доказательств |
| Сканирование зависимостей отказывает | Достижимость, точное исключение и срок | Исправить зависимость или получить ограниченное документированное решение |
| Очистка неполна | Записанные ID, метки владения, журналы цели | Восстановить через владеющий контроллер; сохранить чужие ресурсы |
