# ADR-0013: Сохранение владения отключением GoBGP между перезапусками GoBFD по эпохе спикера

[Английский оригинал](../../en/adr/0013-gobgp-restart-disable-ownership.md).

| Поле | Значение |
|:---|:---|
| Статус | Политика принята; квалификация кандидата отдельно |
| Дата | 2026-11-27 |

## Контекст

Первоначальный контракт актуатора GoBGP v4 хранил отключённых соседей только в оперативной памяти процесса (`Handler.disabled`). Когда GoBFD отключал управляемого соседа по BFD Down и затем перезапускался (например после `SIGKILL` или перезапуска службы) при продолжающем работать локальном `gobgpd`, сессия BFD возвращалась в Up с новым локальным дискриминатором, однако сосед GoBGP навсегда оставался в состоянии `AdminDown/Idle` до ручного вмешательства ([задача #131](https://github.com/dantte-lp/gobfd/issues/131)).

Одновременно классификатор конфигурации трактовал адреса API GoBGP вида `unix:///path` как адреса вне loopback и выдавал ложное предупреждение о незашифрованном удалённом TCP ([задача #132](https://github.com/dantte-lp/gobfd/issues/132)).

Проверка исходников GoBGP v4.10.0 (`pkg/config/oc/util.go`, `pkg/server/server.go`, `pkg/server/fsm.go`) устанавливает два ограничения внешнего API:

1. `ListPeer` возвращает статический флаг `PeerConf.AdminDown` и оперативное состояние `PeerState.AdminState`, но не включает `DisablePeerRequest.Communication` и `DisconnectReason`.
2. Переход в `adminStateDown` обнуляет `Timers.State` (`Uptime`, `Downtime`), `Messages`, `Flops` и `EstablishedCount` в `BgpServer`, поэтому повторный вызов `DisablePeer` для уже отключённого соседа при остановленном GoBFD не оставляет различимого признака в `ListPeer`.

## Решение

### 1. Классификация локальных файловых Unix-сокетов как IPC

Классифицировать значения `gobgp.addr` вида `unix:///abs/path` и `unix:/abs/path` (нормализованный абсолютный путь, пустой authority, отсутствие query, fragment, NUL-байта и префикса абстрактного пространства `@`) как локальное межпроцессное взаимодействие (IPC) через файловую систему. Подавлять предупреждение о незашифрованном не-loopback соединении для таких конечных точек, сохраняя предупреждение для незашифрованного удалённого TCP, `unix-abstract:` и некорректных целей. Источники: [разбор конечной точки](../../../internal/gobgp/endpoint/endpoint.go), [классификатор конфигурации](../../../internal/config/config.go).

### 2. Подтверждённые квитанции владения, привязанные к эпохе спикера

Сохранять долговременную квитанцию владения отключением в `gobgp.state_file` (по умолчанию `/var/lib/gobfd/gobgp-ownership.json`, переопределение через `GOBFD_GOBGP_STATE_FILE`; пустой `gobgp.state_file` оставляет учёт только в памяти) исключительно после успешного завершения `DisablePeer` на локальном Unix-спикере GoBGP с доказуемой идентичностью:

| Поле | Источник | Правило проверки |
|:---|:---|:---|
| `target` | Канонический `gobgp.addr` | Точное совпадение с активной целью клиента |
| `peer_pid`, `peer_uid` | `SO_PEERCRED` ядра на Unix-сокете | Положительный PID и совпадение UID на активном Unix-соединении |
| `socket_dev`, `socket_ino` | Метаданные `stat` подключённого сокета | Совпадение устройства и inode при наличии |
| `boot_id`, `proc_start_time` | `/proc/sys/kernel/random/boot_id`, `/proc/<pid>/stat` | Точное совпадение при доступности чтения; расхождение ведёт к отказу |
| `asn`, `router_id` | Ответ `GetBgp` | Точное совпадение с глобальной конфигурацией спикера |

Запись выполняется через `os.OpenRoot` в доверенном приватном родительском каталоге (без прав записи для группы и остальных, владелец `root` или эффективный UID), создаёт временный файл `0600`, вызывает `fsync` файла, атомарно переименовывает его и вызывает `fsync` каталога. Существующий файл состояния, являющийся символической ссылкой, доступный на запись группе/остальным, принадлежащий постороннему пользователю или содержащий повреждённый JSON, вызывает отказ запуска. Источники: [хранилище квитанций](../../../internal/gobgp/ownership_store.go), [идентичность Unix-пира](../../../internal/gobgp/client.go), [обработчик](../../../internal/gobgp/handler.go).

### 3. Безопасное восстановление и отзыв квитанций

1. Перед вызовом `DisablePeer` GoBFD проверяет `ListPeer`: если `State.AdminState == ADMIN_STATE_DOWN` или `Conf.AdminDown == true`, GoBFD не вызывает `DisablePeer` и не создаёт квитанцию.
2. Аварийное завершение (`SIGKILL`) до возврата ответа `DisablePeer` не оставляет подтверждённой квитанции; после перезапуска владение считается неоднозначным и сосед остаётся административно отключённым.
3. Конечные точки TCP GoBGP не предоставляют ядерного доказательства процесса `SO_PEERCRED`; при перезапуске GoBFD такие квитанции не сохраняются, и соседи под управлением по TCP остаются административно отключёнными после сбоя во время отказа пути.
4. При активном соединении GoBFD подписывается на обновления соседей `WatchEvent`: если сосед с сохранённой квитанцией наблюдается в `ADMIN_STATE_UP` вне инициированного GoBFD вызова `EnablePeer`, квитанция немедленно отзывается, чтобы любое последующее отключение оператором сохранилось.
5. При переходе BFD в Up (либо при начальной сверке снимка, если BFD уже находится в Up при запуске обработчика) GoBFD включает соседа вне памяти текущего процесса только при наличии действительной сохранённой квитанции, полном совпадении идентичности живого спикера, `Conf.AdminDown == false` и `State.AdminState == ADMIN_STATE_DOWN`. Устаревшие и несовпадающие квитанции удаляются без вызова `EnablePeer`.

## Альтернативы

| Альтернатива | Причина отказа |
|:---|:---|
| Хранение владения только в памяти (`Handler.disabled`) | Оставляет отключённого GoBFD соседа навсегда в `AdminDown` после сбоя или перезапуска контроллера ([задача #131](https://github.com/dantte-lp/gobfd/issues/131)) |
| Сохранение адресов соседей без идентичности эпохи спикера | Небезопасно: включает соседа после перезапуска `gobgpd` или замены конфигурации с операторским отключением |
| Определение владения по `DisablePeerRequest.Communication` в `ListPeer` | Недоступно в GoBGP v4.10.0: `NewPeerFromConfigStruct` не передаёт строку причины, а `adminStateDown` обнуляет таймеры и счётчики |
| Хранение квитанций в `/run/gobfd` (`RuntimeDirectory=gobfd`) | Systemd пересоздаёт `RuntimeDirectory=` при `systemctl restart gobfd`, уничтожая квитанции при плановом перезапуске |

## Последствия

- В `gobfd.service` добавляются `StateDirectory=gobfd` и `StateDirectoryMode=0700`; образы контейнеров и `tmpfiles.d` создают `/var/lib/gobfd` с правами `0700` и владельцем `gobfd:gobfd`.
- Перезапуск контроллера при работе через Unix IPC автоматически восстанавливает доказуемо принадлежащие GoBFD отключения после возврата BFD в Up, сохраняя административное отключение для ранее отключённых оператором соседей, статического `Conf.AdminDown = true`, перезапущенного `gobgpd` и неоднозначных TCP-соединений.
- Поскольку GoBGP v4.10.0 обнуляет таймеры и счётчики при `adminStateDown` и не возвращает `Communication` в `ListPeer`, для гарантированного сохранения операторского отключения, выполненного во время остановки `gobfd` на том же PID `gobgpd`, оператор MUST установить `Conf.AdminDown = true` (`UpdatePeer` или `gobgp.toml`) либо выполнить отключение при работающем `gobfd`.
