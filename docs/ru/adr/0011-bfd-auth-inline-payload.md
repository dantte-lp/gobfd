# ADR-0011: Владение встроенным payload аутентификации BFD

| Поле | Значение |
|---|---|
| Статус | Accepted |
| Дата | 2026-10-26 |

## Контекст

[ADR-0010](0010-bfd-auth-value-ownership.md) устранил выделение секции
аутентификации и сохранил принятый wire при проверке. Его срез payload
по-прежнему разделяет backing storage при копировании пакета. Подписи нужно
независимое хранение пароля/digest: локальные измерения после оптимизации
результата digest дают одно выделение для Simple Password и два для hash-режимов.

RFC 5880 ограничивает все поддерживаемые payload аутентификации: пароль
занимает 1–16 байт, MD5 digest — 16 байт, SHA1 digest — 20 байт. Поддерживаемых
payload аутентификации больше 20 байт нет.

## Решение

`AuthSection.Data` — массив 20 байт внутри значения. `DataLen` хранит логическую
длину payload независимо от wire-поля `Len`. Сохраняется отклонение отсутствующих,
коротких, длинных и несогласованных исходящих payload до любой записи wire.
Marshal и Verify проверяют логическую длину до обращения к байтам payload.
Полное нулевое значение обозначает отсутствие секции.

Decode копирует ограниченный payload в локальное значение аутентификации и
публикует его только после проверки секции. Присваивание пакета копирует во
владение и метаданные, и байты payload; повторное использование входа или
изменение другой копии пакета их не меняет. Атомарность изменения заголовка
при ошибке decode не обещается; ingress по-прежнему отбрасывает любую такую ошибку.

Встроенный Sign читает неизменяемые ключи пакета через существующий приватный
accessor и копирует байты в память пакета. Публичные accessor хранилища ключей
сохраняют копии во владение вызывающего кода. Hash signing заменяет встроенный
ключ digest по значению и записывает только заданную RFC длину digest. Пакет
не раскрывает backing storage хранилища или payload другого пакета.

Читающие Verify и DemuxWithWire продолжают передавать пакеты по значению.
Hash verification сохраняет ограниченный scratch PDU, точные длины digest,
сравнение за постоянное время и обновление replay state после успеха. Обычный
и overlay-приёмники сохраняют полный аутентифицированный datagram для проверки
после возврата pooled input; собственный decoded payload не отменяет потребность
в wire. Повторно разбирать сохранённую копию им больше не требуется.

Внутреннее Go-представление меняется; форматы protobuf, конфигурации и BFD wire
сохранены. Неподдерживаемые будущие типы аутентификации отклоняются; поддержка
большего payload требует отдельного решения и квалификации.

## Последствия

Обязательная цель — нулевые выделения пяти встроенных Sign и пути
аутентифицированного владельца/event loop с настоящими метриками. Квалификация
охватывает независимые векторы, неверные длины и ключи, копии пакетов, повторную
подпись, изоляцию хранилища, race/fuzz и обе поддерживаемые цели компиляции.
Локальные размеры linux/amd64: `ControlPacket` 60 байт и `AuthSection` 28 байт
вместо 64 и 32. Элемент очереди приёма сохраняет 160 байт из-за выравнивания;
меньший пакет не сокращает этот элемент. Размеры не задают удерживаемый RSS.
Бенчмарки выделений не квалифицируют UDP, native arm64, масштаб,
распределения таймеров или релизный кандидат.

Beads `gobfd-qj0.8.2.8.6.3.2.2` владеет реализацией и квалификацией исходников;
полное сравнение остаётся в `gobfd-qj0.8.2.8.6.3.2`. Этот ADR заменяет ADR-0010,
сохраняя его решения о передаче значений и неизменяемой проверке.
