# ADR-0008: Граница экспериментального предварительного выпуска

[English original](../../en/adr/0008-experimental-prerelease-boundary.md).

<a id="adr-0008-граница-экспериментального-prerelease"></a>

| Поле | Значение |
|:---|:---|
| Статус | Политика принята; квалификация кандидата и публикация отдельно |
| Дата | 2026-10-30 |

## Контекст

Экспериментальный `v1.0.0-alpha.1` предоставляет реализованное поведение до завершения квалификации стабильной v1. Сопровождающий разрешает этот канал предварительных выпусков 2026-10-30. Разрешение распространяется на проверенный процесс его поставки, не отменяет стабильную приёмку и не разрешает посторонние удалённые изменения.

[SemVer §9](https://semver.org/spec/v2.0.0.html#spec-item-9) определяет предварительный выпуск как нестабильный. Суффикс версии не доказывает соответствие протоколу, поддерживаемый масштаб или совместимость развёртывания. Эти границы определяют [матрица RFC](../08-rfc-compliance.md) и доказательства точного кандидата.

## Решение

Принимать в экспериментальном канале только канонические теги `v1.0.0-alpha.N`, где `N` — положительное десятичное целое без ведущих нулей. Привязывать каждый аннотированный неизменяемый тег к точному проверенному HEAD ветки `release/v1.0`. Сохранить проверки стабильных тегов и требования квалификации.

| Этап | Владелец и требование |
|:---|:---|
| Предложение выпуска | Release Please создаёт только PR выпуска; `skip-github-release: true` исключает второго владельца тега и выпуска |
| Запись выпуска | Проверенный PR обновляет манифест версии и оба отобранных датированных раздела changelog; сохранить опубликованную историю и ссылки на реальные PR изменений |
| Разрешение тега | Сопровождающий отправляет проверенный аннотированный тег после merge и обязательных проверок; перемещение, удаление и повторное использование запрещены |
| Создание черновика | GoReleaser собирает версионные продукты и черновик GitHub prerelease; основная загрузка отключена до финализации пакетов |
| Независимая проверка | Проверить точные исходники, слитый PR выпуска, примечания, 12 артефактов, контрольные суммы, SBOM и доказательства версионных OCI до публикации |
| Публикация | Публиковать с `--prerelease --latest=false`; сохранить стабильные GitHub latest и псевдонимы OCI |

[Release Please](https://github.com/googleapis/release-please-action/blob/45996ed1f6d02564a971a2fa1b5860e934307cf7/README.md) отвечает за предложение, а не публикацию. Отправка тега сопровождающим запускает существующий workflow выпуска; тег, записанный с `GITHUB_TOKEN`, не считается источником запуска следующего workflow. Эту границу определяют [правила событий GitHub](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow#triggering-a-workflow-from-a-workflow).

Путь alpha использует общие со стабильным выпуском проверки артефактов и идентичности. `release-pr-check` проверяет целевую ветку слитого PR выпуска, merge commit, версию манифеста и оба заголовка changelog, затем добавляет проверенный URL в примечания выпуска. `release-promote` отклоняет alpha. Публикация alpha повторно проверяет версионные OCI вместо требования направить стабильные псевдонимы на кандидата.

Функциональные отказы и нарушения безопасности в заявленной области alpha блокируют публикацию. Требовать сборки точного кандидата, критические регрессии протокола, аутентификации, reload и управления, новую оценку безопасности зависимостей, проверки жизненного цикла пакетов и полные проверенные доказательства черновика. Указать оставшиеся ограничения в обоих changelog и теле выпуска; принятие политики не является успешным результатом проверки.

## Альтернативы

Сохранение пути только для стабильных версий исключает экспериментальный выпуск на время окончательной квалификации. Создание выпуска силами Release Please одновременно с GoReleaser создаёт конкурирующее владение тегом и черновиком. Публикация alpha через продвижение стабильных псевдонимов меняет стабильный канал поставки. Отдельное предложение через PR и проверенная публикация предварительного выпуска исключают эти конфликты.

## Последствия

Alpha не подтверждает совместимость стабильного API, поддерживаемый масштаб сессий, полное покрытие RFC или готовность к production. Строгая приёмка окон CPU, нативное сравнение Control/Echo A/B, калиброванные эталонные распределения, 24-часовой прогон и окончательная квалификация на линии остаются отдельными условиями стабильного выпуска. Короткий стенд или суммарный процент CPU не заменяют эти измерения.

Исходный кандидат с закреплёнными потоками Control/Echo не мог выполнить эталонный предел 48 потоков при 1000 владельцев. Локальное указание сопровождающего от 2026-10-28 по объединению отдельно разрешает интеграцию исходников, снимающую постоянное закрепление владельцев. Это не закрывает нативное сравнение A/B, предел 48 потоков, работу в течение 24 часов или окончательные проверки на линии. Сохранить консервативный бюджет PID из [ADR-0007](0007-workload-phase-accounting.md) до пересмотра на основании измерений.

Выполнять длительную квалификацию независимо от интерактивного SSH в отдельно разрешённом окружении. Связать ресурсы гостевой системы, часы, исходники и бинарник с сохранёнными журналами и конечным результатом. Поставка alpha не закрывает эту работу и не меняет последнее принятое стабильное состояние в `master`.
