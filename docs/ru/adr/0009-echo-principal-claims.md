# ADR-0009: Права principal на общий Echo wire

| Поле | Значение |
|---|---|
| Статус | Accepted policy; локальная квалификация отдельно |
| Дата | 2026-10-25 |

## Контекст

Исключительный флаг source API/config в Echo не представляет совместное владение.
Повторное создание через API выделяет новый discriminator и sender, а удаление
только по discriminator может удалить сессию другого principal. При разделении
wire также нужно сохранить RX после удаления исходного декларативного source.

## Решение

Использовать существующие `SessionOwner`, полученный из транспорта
`apiOwnerFromContext` и сравнимый `SessionKey`. Идентичность Echo содержит peer/local
адреса после unmap и точный интерфейс; zones остаются частью адресов. Составной
ключ исключает коллизии разделителей. Интервал TX и Detect Multiplier должны
совпадать с действующим wire до принятия дополнительной claim.

При существующем порядке блокировок lifecycle/ownership/registry сохранять один
Echo wire и sender lease на идентичность и множество claims владельцев. Повторный
допущенный вызов того же владельца — no-op; совместимый владелец config или API
разделяет wire. Несовместимый набор параметров возвращает `FailedPrecondition`
до выделения ресурсов или изменений. Владельцы API определяются проверенным
транспортом, а не полями запроса. Unix UID, TLS URI, TLS DNS и анонимный локальный
владелец при явно включённом небезопасном режиме сохраняют существующие
пространства имён principal. Наблюдение без изменений остаётся общим для демона.

Удаление освобождает только claim вызывающего. Вызывающий без claim получает
`PermissionDenied`; отсутствующий discriminator возвращает `NotFound`. Только
последняя claim завершает wire. Освобождение и shutdown ожидают завершения Echo
owner перед закрытием sender lease, вне блокировок Manager. Ошибки очистки
остаются наблюдаемыми.

Физический lease Echo удерживает приёмный listener независимо от того, какой
source создал его первым. Удаление конфигурации должно сохранить RX/TX для
оставшейся API claim. Освобождение последнего wire закрывает его ссылку на RX;
конфигурационные ссылки source сохраняют независимый жизненный цикл.

Реконсиляция проверяет полный desired set относительно всех действующих
владельцев, затем подготавливает новые config claims до освобождения устаревших.
Ошибка подготовки откатывает только claims текущего прохода, сохраняет прежние
config claims и никогда не удаляет оставшиеся API claims. Число claims и число
физических wire учитываются раздельно.

## Последствия

- Повторный одинаковый Echo Add идемпотентен; List/Watch описывают один wire,
  даже если его разделяют несколько владельцев. Изменение claims само по себе
  не публикует события жизненного цикла wire и не сбрасывает протокольное
  состояние, discriminator или порт источника.
- Проверка preview/readiness по-прежнему предшествует каждому Add, включая
  повторы. При отсутствии готовности запрос может завершиться ошибкой при
  сохранении действующей claim; List/Delete доступны согласно политике управления.
- Совместимые Go-методы создания/удаления используют собственного compatibility
  owner и не могут освободить claim конфигурации или другого API principal.
- Авторизация principal относится к плоскости управления. Она не аутентифицирует
  возвращённые Echo-пакеты и не квалифицирует межузловую пересылку, IPv6 link-local,
  безопасность RFC 9747 или поддерживаемый масштаб. Echo остаётся предварительной
  реализацией.
